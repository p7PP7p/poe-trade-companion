# PoE Trade Companion — 市集增强（Chrome / Edge 扩展）

面向《流放之路》国际服官方市集（https://www.pathofexile.com/trade）的浏览器增强扩展，基于 **Manifest V3**，界面全中文。

当前版本：**0.3.5**（筛选器搜索框支持**中英双向匹配**：输入中文能命中对应选项、输入英文照常命中，且无论中英命中，提交给官网的查询值始终是官网期望的英文枚举 / 选项 id；v0.3.3 的「加载中」修复与 v0.3.4 的汉化补齐均不回退）。当前适配赛季：**Covens（0.3.1）**，赛季名与接口路径可通过远端配置热更新，无需重新提审发版。

## 1. 功能一览

| 功能 | 说明 |
| --- | --- |
| 搜索结果价格增强 | 拦截市集搜索接口返回，在每条结果行内插入估算价徽标（中位数 / 区间 / 相对挂价的偏离百分比），支持按偏离度着色告警 |
| 物品快速估价 | 在侧栏「快速估价」粘贴游戏内 Ctrl+C 复制的物品文本，输出价格区间、中位数、建议售价（P40）与样本量；「价格分析」Tab 内还可对当前搜索结果一键批量估价（每批 10 条、上限 200 条，带进度条） |
| 收藏与降价追踪 | 任意结果可加入收藏（记录当时的挂价快照），后台按设定间隔巡检，价格下跌超过阈值时发送系统通知，并在侧栏「收藏追踪」以涨跌幅高亮 |
| 一键复制交易私聊 | 结果行「复制」按钮 / 侧栏列表项，一键把该条挂售的官方 whisper 文本写入剪贴板 |
| 赛季自适应 | `config/remote.json` 远端配置 + 本地缓存与过期兜底，赛季名 / 接口路径 / 选择器 / 最低版本要求均可远端下发；同时内置硬编码兜底，断网也不会失效 |
| 页面汉化（0.2.0 起，0.2.2 修复） | 把官方市集页面的筛选器面板、Tab、按钮、下拉选项、物品类别、结果行状态词、分页与价格单位替换为中文；双通道实现（数据层改写 + DOM 层翻译），DOM 层采用「父元素整块聚合 + 文本节点兜底」两级匹配，可正确翻译被 React 拆成多个子节点的按钮与标题；支持自定义词库与远端词库热更新，可一键关闭并还原英文，不改动页面结构与站点行为 |
| 回归修复（0.3.3） | ① **查询结果永久加载中**：0.3.2 的分词组合兜底把 `TEXT_FIELDS` 扩到 `type`，结果响应里 `listing.price.type` 的机器枚举值 `~price` / `~b/o` 被译成 `~价格`，官网渲染行时解析失败，列表停在「加载中」。0.3.3 把 `type` 移出改写字段、对含 `~` 的机器标记一律跳过、`translateText` 遇 `~` 直接返回 null |
| 回归修复（0.3.3） | ② **汉化被 React 冲掉**：DOM 层聚合翻译原本把命中元素的子节点整体摘除再追加中文节点，官网 React 持有的文本节点被移除后，后续 diff/commit 找不到目标节点、更新写不进真实 DOM，界面回退英文且结果区渲染中断。0.3.3 改为**就地改写 `nodeValue`**：保留每个原始文本节点的身份与父子关系，只改内容；聚合写入的节点加独占锁，避免聚合通道与逐节点通道互相覆盖；关闭汉化时按快照原样还原 |
| 筛选项补全（0.3.2） | 官方筛选器里大量选项由「已知词条 + 已知词条」拼装而成，逐条登记会无限膨胀，故新增**分词组合兜底**：先把 `Sell (Any)`、`Damage / 100%`、`One-Handed melee Weapon`、`Claws (Claw)` 按标点与括号切分，再对单词做贪心最长匹配、用词库拼装译文（括号转全角、数值前后自动补空格）；任一单词未命中即整体放弃、保留英文原文，绝不产出半中半英。DOM 层与数据层（`inject.js`）同一套算法 |
| 搜索框中英双向匹配（0.3.5） | 筛选器全量搜索框与快捷列表支持中英文双向检索：输入「青玉护身符」能命中 `Turquoise Amulet`、输入「细剑」能定位 `weapon.rapier`，输入英文仍按原逻辑命中；匹配阶段在内存中完成换算，`option.id` / `filter.id` / 提交的查询 JSON 一律保持官网英文枚举，不会因中文输入把查询值改写成中文而导致结果为空 |
| 悬浮球与侧栏 | 页面右侧可拖拽悬浮球，点击展开 Shadow DOM 抽屉侧栏（也可用快捷键 `Ctrl+Shift+E`），样式与站点完全隔离 |

侧栏包含三个 Tab：**价格分析**（含批量估价）/ **快速估价** / **收藏追踪**。

## 2. 安装（加载已解压扩展）

1. 解压 `poe-trade-companion-v0.3.3.zip`（或直接使用 `poe-trade-companion/` 目录，zip 内顶层目录为 `poe-trade-companion/`）。
2. Chrome 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
3. 打开右上角 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择解压出的 `poe-trade-companion` 目录（含 `manifest.json` 的那一层）。
5. 打开 https://www.pathofexile.com/trade/search/Covens ，页面右侧出现悬浮球即安装成功。
6. 安装后官方市集页面默认即为中文；若想恢复英文原貌，可在设置页「页面汉化」区块关闭或点「在当前页面立即还原英文」（详见 4.4）。

> 扩展需要 `storage`、`alarms`、`notifications`、`clipboardWrite`、`scripting`、`tabs` 权限，仅用于本地缓存、定时巡检、降价通知、复制私聊文本与设置页跳转，不采集任何账号信息。

## 3. 使用说明

### 3.1 搜索结果价格增强
打开任意市集搜索结果页，扩展会自动接管该页的搜索响应：

- 每条结果行右侧出现徽标，形如 `≈ 12.4 div · -18%`；
- 绿色 = 低于市场价（可能是捡漏），灰色 = 接近市场价，红色 = 明显高于市场价；
- 徽标数据来自对同类物品的批量取样，样本不足时显示 `样本不足`，不会给出误导性结论。

可在设置页关闭行内徽标（`设置 → 行内价格徽标`），或调整取样条数与偏离告警阈值。

### 3.2 物品估价
**单件估价**
1. 在游戏中把鼠标移到物品上，按 `Ctrl+C` 复制物品文本；
2. 打开侧栏 → **快速估价** Tab → 粘贴到文本框；
3. 点击「估价」，依次看到「正在解析物品… → 正在提交搜索… → 正在拉取挂单价格…」，最后给出物品名、基底、稀有度、iLv、样本量、价格区间、中位数与建议售价。

也可以在任意市集页按 `Ctrl+Shift+E` 展开/收起侧栏（快捷键可在设置页修改或关闭）。

**批量估价**
在 **价格分析** Tab 点「批量估价当前结果」，对当前搜索结果逐条估价：扩展每 10 个 id 为一批发起请求，最多 200 条，过程中显示进度条与「已估价 N 条」，完成后给出整体建议价。

估价结果仅供参兑，实际成交价受词缀、品质、赛季供需影响。

### 3.3 收藏与降价追踪
- 结果行点击星标 → 加入收藏，同时记录当前最低挂价作为基线；
- 侧栏 **收藏追踪** Tab 查看全部收藏、当前价、基线价、涨跌幅；
- 后台 `alarms` 每 30 分钟巡检，跌幅超过阈值（默认 10%）时弹出系统通知；
- 收藏数据保存在 `chrome.storage.local`，可随时移除或清空。

### 3.4 复制交易私聊
- 结果行「复制私聊」：复制该条挂售的完整私聊文本；
- 侧栏列表每一项也有复制按钮；
- **合规约束**：扩展只负责把文本写入剪贴板，绝不自动发送、自动点击「邀请组队」或自动接受交易，所有交互仍需玩家手动完成。

## 4. 页面汉化

0.2.0 引入、0.2.2 修复。默认**开启**（安装后打开官方市集页面即为中文），如需英文原貌按 4.4 关闭即可。扩展自身侧栏、弹窗与设置页始终为中文，不受该开关影响。

### 4.1 汉化范围

采用**双通道**实现，互不依赖，任一通道失效时另一通道仍能兜底：

| 通道 | 实现位置 | 作用对象 |
| --- | --- | --- |
| A 数据层 | `content/inject.js`（MAIN world） | 拦截 `/api/trade/data/*` 响应，递归改写其中的 `text` / `label` / `title` 字段，从数据源头把筛选器词条、下拉选项、物品类别、词缀分组变为中文；赛季新增词条只要命中词库即可生效，不依赖 DOM 结构。0.3.1 起同时拦截 `/api/trade/fetch/*`（搜索结果与详情），按词缀自带的 `hash`（`stat.explicit.stat_xxx`）直查 18193 条官方词缀词库、把数值回填成中文词缀行，并把物品属性条目名（`Armour` / `Energy Shield` / `Level`）一并中文化 |
| B DOM 层 | `content/localizer.js`（ISOLATED world） | **两级匹配**：①父元素聚合——对含多个子节点的元素取 `innerText` 整段匹配，命中后把该元素内容合并为单个文本节点（解决 React 拆分）；②文本节点兜底——逐节点精确匹配 + 句式模板；另处理 `placeholder` / `title` / `aria-label` 属性；配合 `MutationObserver` 处理分页、筛选重渲染后的新节点 |

**0.2.2 修复说明（为什么之前大量固定字段不翻）**：官方市集页面由 React 渲染，`Add Stat Filter`、`BULK ITEM EXCHANGE`、`Search Listed Items` 这类按钮/标题在 DOM 里被拆成「图标元素 + 多个 `<span>` + 多个文本节点」。旧版只做文本节点级精确匹配，单个节点往往只有 `Add`、`Stat Filter` 片段或前后空格，整句无法命中词库，于是界面上出现大面积未翻译。0.2.2 先用父元素 `innerText` 整串去匹配，命中即整块替换为单文本节点，翻译完整且不再被 React 的节点切分影响。

覆盖的具体位置（均可验证命中）：

| 页面位置 | 原文示例 | 汉化后 |
| --- | --- | --- |
| 筛选器面板标题 / Tab | `Type Filters` / `Trade Filters` / `Misc Filters` | 类型筛选 / 交易筛选 / 其他筛选 |
| 按钮与操作文案 | `Add Stat Filter` / `Reset Filters` / `Search Listed Items` | 添加属性筛选 / 重置筛选 / 搜索在售物品 |
| 区块标题 | `BULK ITEM EXCHANGE` / `Item Category` | 批量物品交易 / 物品类别 |
| 下拉选项、物品类别 | `One Handed Sword` / `Chaos Orb` / `Jewellery` | 单手剑 / 混沌石 / 珠宝 |
| 结果行状态词 | `Listed 3 days ago`、`Listed just now`、`Online 5 minutes ago` | 上架 3 天前、刚刚上架、5 分钟前在线 |
| 库存 / 数量 / 分页 | `3 in stock`、`x20`、`Page 2 of 17`、`Show 50 results` | 库存 3、×20、第 2 / 17 页、显示 50 条结果 |
| 价格与单位 | `Price: 2 divine`、`12 chaos` | 价格：2 神圣石、12 混沌石 |
| 物品属性字段 | `Item Level 86`、`Minimum Physical Damage`、`Damage per Second` | 物品等级 86、最低物理伤害、每秒伤害 |
| 属性与词缀短语 | `60% increased Armour`、`Adds 25 to 40 Physical Damage` | 护甲提高 60%、附加 25 至 40 物理伤害 |

**不翻译的内容**（有意保留英文）：卖家备注与角色名、装备的英文基底名与暗金名（词库未收录时）、聊天/私聊文本、URL 与数值本身。扩展不会替换 `innerHTML` 结构（仅在聚合命中时合并该元素的文本内容），页面事件绑定与站点脚本状态不受影响。

### 4.2 词库构成与覆盖率

内置词库位于 `lib/i18n-dict.js`，0.2.2 起为**分层结构**（设置页「页面汉化」区块底部会实时显示这些统计），并同步导出到 `config/i18n-zh.json`：

| 分层 | 条数 | 作用 |
| --- | --- | --- |
| 界面文案 `ui` | 179 | 筛选器标题、Tab、按钮、区块标题、物品属性条目名（`Armour` / `Energy Shield` / `Level` / `Quality` 等） |
| 物品类别 `category` | 84 | 武器/护甲/珠宝/地图等类别与筛选分类 |
| 通货与专名 `static` | 32 | 混沌石、神圣石等固定专名 |
| 术语 `terms` | 253 | 属性、词缀与游戏机制术语，同时用于句式模板的 `$1` / `$2` 参数翻译 |
| 补漏界面词 `ui_gap` | 53 | 0.2.2 实测补入的高频界面词（`Reset Filters`、`Item Level`、`Str/Dex/Int`、`Whisper Seller` 等）与时间/通货单位 |
| 补充词 `supplement` | 42 | 早期补入的高频词，优先级最低 |
| 句式模板 `patterns` | 98 | 84 条词缀/属性句式（`+# total to Level of all (.+) Gems` 等）+ 14 条动态数字与前后缀模板（`Listed N days ago`、`N in stock`、`Page N of M`、`Show N results`、`Price: N divine`、`Minimum/Maximum XXX`、`Has no XXX` 等） |
| 精确 id 映射 `byId` | 8 | 按数据层词条 id 直译，避免英文同形词误译 |

另有一份**独立词缀词库** `config/i18n-stats-zh.json`（内置副本 `lib/i18n-stats-zh.js`），来自官方 `/api/trade/data/stats` 的 `id ↔ 中文文本` 对照，**18193 条**，覆盖 explicit / implicit / crafted / enchant / fractured / scourge 等全部词缀域。它按词缀 `id` 精确命中，不受英文句式变化影响，与上面的界面词库互不干扰；可用远端 `i18n.statsUrl` 热更新。

叠加合并后：`fullDict` **585 条**精确词条 + **98 条**句式模板（「仅界面文案」档使用 `uiDict` 360 条，即 `supplement` + `ui_gap` + `ui` + `category` + `static`）。

覆盖率口径：汉化是**词条/模板命中式**翻译，命中即整段替换，**未命中的文案保持英文原样**，不会出现空白、乱码或占位符残留；0.2.2 已关闭「按词块拼接」的兜底逻辑，因此不会再出现「获得 # 生命 每 敌人 Hit 带 攻击」这类半中半英的拼接结果——宁可保留英文，也不输出劣质译文。

- 界面层（筛选器面板、Tab、按钮、区块标题、下拉选项、物品类别、状态词、分页、价格单位）：已按实测取样 82 条官网高频文案验证，**命中率 100%**；
- 属性与词缀（筛选器词缀下拉、结果行词缀行）：常用属性、抗性、伤害、防御类短语已覆盖；
- 官方若改动页面文案（如 `Show N results` 改为 `N results shown`），对应模板失效时该处回退英文，等待词库更新即可，不影响其余位置。

### 4.3 扩充与导入自定义词库

词库优先级：**自定义词库 > 远端词库 > 内置词库**，后者只作兜底，不会覆盖前者的译法。

**方式一：设置页直接维护（适合少量修正）**

1. 设置页 → 「页面汉化」→ **自定义词库** 文本框；
2. 每行一条，格式 `英文原文=中文译名`，例如 `Mirrored=镜像`、`Recombinator=重组器`；
3. 点 **保存自定义词库**，底部显示已保存条数与自定义词库总条数；保存后打开的市集页面会即时应用，无需刷新；
4. 点 **清空词库** 可移除全部自定义词条，回退到内置与远端词条。

校验规则：单条英文 ≤120 字符、中文 ≤200 字符，不支持 HTML 标签（含 `<` `>` 的条目会被跳过）；格式不正确的行不会中断保存，扩展会保存合法条目并提示"第 X、Y 行格式不正确（应为「英文=中文」），已跳过"。

**方式二：远端词库热更新（适合给多人分发、赛季批量补词）**

扩展目录内已附带可直接托管的样例文件 `config/i18n-zh.json`（由内置词库导出，分层结构，约 31 KB）：

```json
{
  "_meta": { "version": "0.2.2", "schemaVersion": 2, "counts": { "ui": 148, "category": 84, "static": 32, "terms": 253, "ui_gap": 53, "supplement": 42, "patterns": 98, "byId": 8 } },
  "ui":        { "Item Category": "物品类别", "Type Filters": "类型筛选", "Add Stat Filter": "添加属性筛选" },
  "category":  { "One Handed Sword": "单手剑", "Jewellery": "珠宝" },
  "static":    { "Chaos Orb": "混沌石", "Divine Orb": "神圣石" },
  "terms":     { "increased Life": "生命提高", "Fire Resistance": "火焰抗性" },
  "ui_gap":    { "Reset Filters": "重置筛选", "day": "天", "divine": "神圣石" },
  "supplement":{ "Online": "在线", "Offline": "离线" },
  "patterns":  [ { "p": "^Listed (\\d+) (second|minute|hour|day|week|month)s? ago$", "r": "上架 $1$2前", "flags": "i" } ],
  "byId":      { "explicit.stat_3299347043": "生命上限 +#" }
}
```

发布步骤：

1. 把 `config/i18n-zh.json` 上传到任意可公开访问的 HTTPS 地址（GitHub raw、对象存储、自己的静态站点均可）；
2. 修改 `config/remote.json` 中的 `i18n.dictUrl` 指向该地址（`i18n.version` 用于标识词库版本号，便于自查）；
3. 用户端每 **6 小时**自动拉取一次，拉取失败时优先使用过期缓存，再失败则静默回退内置词库，页面不会报错；
4. 改完想立刻生效：在设置页点 **测试拉取**（会强制重新拉取远端配置与词库），或刷新已打开的市集页面；每次拉取结果会缓存 6 小时。

格式要点（务必注意）：

- 加载器会把分层字段按优先级从低到高**摊平**成一张词表：`supplement` < `ui_gap` < `ui` < `category` < `static` < `terms` < `dict`（兼容旧版单层 `dict` 字段），远端词条**整体优先于内置**；
- `patterns`（句式模板）随扩展代码发布，远端只做参考不会被替换；模板里 `p` 为用于匹配的正则源码，`r` 为替换模板（`$1` / `$2` 引用捕获组，捕获内容会先用词条翻译），`r` 以 `!` 开头表示允许结果中保留英文实体名；
- 单条英文 ≤120 字符、中文 ≤200 字符，值必须是字符串，含 `<` `>` 的条目会被加载器丢弃；
- 文件需为合法 UTF-8 JSON，字段缺失或格式错误时整份远端词库视为无效并回退内置。

### 4.4 关闭汉化并一键还原英文

三种方式，均为**即时生效、无损还原**：

1. **关闭开关**：设置页 → 「页面汉化」→ 关闭「启用官网市集汉化」→ 点 **保存设置**；扩展会把配置变更同步到已打开的市集页面并即时还原英文，若某页面未响应（例如设置保存时该页处于后台），刷新一次即可；
2. **一键还原按钮**：设置页 → 「页面汉化」→ 点 **在当前页面立即还原英文**，扩展会关闭汉化并广播到所有已打开的市集页面，当前页面立刻恢复英文，提示"已关闭汉化：已打开的市集页面即时还原英文，无需刷新"；
3. **卸载扩展** 或停用扩展：页面刷新后恢复官方原样。

还原机制说明：汉化并不销毁原文——每处被改写的文本节点/属性都保留了原始值，关闭时逐条写回并按 id 恢复；父元素聚合替换前会把原始 `innerHTML` 结构快照存入内存，还原时按快照重建，因此按钮图标与事件绑定不丢失。数据层改写只作用于本次页面加载的响应副本，**关闭「数据层汉化」开关后需刷新一次市集页面**（重新请求 `/api/trade/data/*`）才能完全恢复英文。

> 档位默认值变更：0.2.2 起「汉化范围」默认值为 **界面文案 + 物品名称与词缀**（`full`）。从 0.2.0/0.2.1 升级时，扩展会在首次启动自动把旧默认值 `ui` 迁移为 `full`（只迁移一次，之后你在设置页手动改回 `ui` 不会被覆盖）。

三个独立开关便于按需降级：

| 开关 | 默认 | 关闭后的效果 |
| --- | --- | --- |
| 启用官网市集汉化 | 开 | 全站恢复英文，扩展侧栏与弹窗不受影响 |
| 数据层汉化（筛选器词条） | 开 | 停止改写接口响应，筛选器与下拉选项回英文（需刷新页面），DOM 层仍翻译状态词与按钮 |
| 正则模板翻译（动态文案） | 开 | 停止模板匹配，只做整词精确匹配；`Listed 3 days ago` 这类动态文案保持英文 |

### 4.5 已知边界

- **界面字段高覆盖**：筛选器面板、Tab、按钮、区块标题、下拉选项、物品类别、状态词、分页、价格单位等界面固定文案已按官网实测取样验证，命中即翻译，不经词块拼接；
- **筛选词缀高覆盖**：筛选器里的词缀/属性下拉（`+#% to Fire Resistance`、`Adds N to M Physical Damage`、`#% increased Armour` 等）由术语层 + 句式模板共同覆盖；
- **装备词缀已高覆盖**：0.3.1 起物品面板与结果行里的显式/固有/工艺/附魔词缀，改由数据层按词缀 `hash` 直查 18193 条官方词缀词库后回填数值，实测官方真实搜索结果 51 行词缀 **50 行中文化（98%）且数值 100% 一致**；个别复合词缀（如多段拼接的独特词缀）仍保留英文；
- **英文基底名与暗金名保留英文**：装备名、暗金名默认不译（保留可检索性与玩家习惯），可在自定义词库中按 `英文名=中文名` 自行补充；
- **卖家备注、角色名、聊天文本**不翻译。

### 4.6 筛选器搜索框中英双向匹配（0.3.5）

官网筛选器的全量搜索框（下拉多选 multiselect）只按选项英文原文或内部 id 匹配，汉化后展示成中文，用户输入中文自然搜不到。0.3.5 增加 `content/search-bridge.js`（MAIN world，紧随 `inject.js` 注入）做双向桥接：

| 环节 | 做法 |
| --- | --- |
| 反向索引 | 由 `i18n-dict`（4801 条）建「中文→英文」，再由 `i18n-filters-zh` 的 **id 型枚举键**（如 `weapon.rapier`→细剑、`armour.boots`→鞋子、`securable`→立即购买）建**精确枚举索引**；顺序键（`__N`）不参与反查，避免张冠李戴 |
| 组件层匹配 | 给 multiselect 的 Vue 实例包装 `filter(option,label,search)`：先走原生匹配，未命中再按「展示中文 / 英文原文 / 词库反查 / 精确枚举」四路补判，兼容「按中文文案匹配」与「按 id/英文匹配」两种引擎 |
| 兜底改写 | 拿不到组件实例时，监听 `input` 事件：若当前输入零候选，则把输入框内容换成等价查询（中文→英文枚举、英文→中文），并把原始输入存在 `data-ptc-query-zh` 便于回看；改写后仍零候选则不改，避免乱动用户输入 |
| 查询值安全 | 只改输入/匹配过程，`option.id`、`filter.id`、`type` 枚举、`~price` 等机器标记一律不动；`rewriteFilters` 记录的英文原文快照为 non-enumerable，不会随 JSON 序列化提交给官网 |
| 防误伤 | 匹配判定按整词/子串双向比对，`饰品` 不会命中 `戒指`、`护身符` 不会命中 `腰带`；选项文案兜底顺序调整为 id → 英文原文 → 分词词库 → 位置键，修正了此前带 id 选项被位置键错配成「任何」的问题 |

自测覆盖 36 项（反向词典、精确枚举、双向匹配、两种引擎补丁、查询值不变量、兜底改写）与数据层回归 12 项，全部通过。仍需真实浏览器端到端复验：不同赛季筛选项集合变化时，以 id 型映射为准可自动适配，缺失项会保留英文原样而非误译。

## 5. 赛季自适应机制

优先级：**本地缓存（未过期） → 远端 `config/remote.json` → 内置兜底常量**。

- 远端配置默认地址：`https://raw.githubusercontent.com/<用户>/poe-trade-companion/main/config/remote.json`
- 可在设置页改为自己的仓库地址，并点「测试远端配置」验证连通性；
- 远端下发的字段包括：`selectors`（结果行、行内价格、物品名等多候选选择器）、`api`（搜索 / 取详情接口路径）、`league` 默认赛季、`leagueAliases` 旧赛季名映射、`notice` 公告文案、`minExtensionVersion` 最低版本要求；
- 新赛季只需改远端 JSON 的 `league` 与 `selectors`，用户端最多延迟一个缓存周期（默认 6 小时）自动生效，无需发新版本；
- 远端可下发 `minExtensionVersion`：本机版本低于该值时，工具栏弹窗顶部显示「插件有新版本，请更新（当前 vX，最新 vY）」黄色横幅；设置页点「测试远端配置」也会列出该字段，便于确认是否被要求升级；
- 远端不可达时静默回退内置常量，页面功能不受影响。

## 7. 实现要点

- **双世界通信**：`inject.js` 运行在 MAIN world，拦截 `POST /api/trade/search/{league}` 与 `GET /api/trade/fetch/{ids}?query={searchId}`，通过 `window.postMessage` 把结果交给 ISOLATED world 的 `content.js`；页面 API 调用天然携带同源 Cookie，无需扩展自己持有会话。
- **DOM 增强容错**：所有选择器走多候选数组 + `querySelectorAll` 逐个尝试，定位失败时静默降级（不抛错、不插入空徽标）；`MutationObserver` 200ms 节流处理分页与筛选重渲染。
- **请求节流**：所有扩展发起的网络请求统一经过 `rate-limiter.js` 队列，默认最小间隔 260ms，遇 `429` 指数退避，避免触发官方频率限制。
- **样式隔离**：侧栏全部渲染在 Shadow DOM 内，站点样式无法穿透，扩展样式也不会污染站点。
- **汉化双通道与无损还原**：数据层在 MAIN world 改写 `/api/trade/data/*` 的 `text` / `label` / `title` 字段（`type` 为查询枚举，一律保持原样，避免页面用中文值发请求导致搜索失效）；DOM 层优先做**父元素整块聚合**——对含多个子节点的元素取 `innerText` 整段匹配，命中后清空子节点、把图标类子元素（`svg`/`img` 等）原位放回、追加唯一译文文本节点，因此 React 把按钮拆成多个 `<span>` 也能完整翻译，且按钮图标不丢；未命中再退回文本节点级精确匹配与句式模板，`placeholder`/`title`/`aria-label` 单独处理。所有被替换的子节点与原文都留存在内存记录中，关闭开关或点「立即还原英文」时按原顺序逐条写回，不改 `innerHTML`、不重建未涉及的节点，站点事件绑定与脚本状态不受影响。
- **词库分层合并**：内置 `lib/i18n-dict.js` 内按 `supplement` < `ui_gap` < `ui` < `category` < `static` < `terms` 的优先级逐层摊平成 `fullDict`（`uiDict` 供「仅界面文案」档使用），再叠加远端 `i18n.dictUrl`（缓存 6 小时，失败回退过期缓存再回退内置）→ 用户自定义词库，后者整体优先；所有词条在合并前做长度与字符校验，非法条目丢弃而非报错。
- **不做无约束的词块拼接**：0.2.2 移除了「见到就拼」的降级路径；0.3.2 起的兜底是**受约束的分词组合**——只按标点与括号切词，每个词必须整词命中词库，任一单词失配即整体放弃并保留英文原文，产出结果还要过一道「残留英文即丢弃」自检，因此不会出现半中半英文案。完整匹配链路为「精确词条 → 句式模板 → 分词组合兜底 → 保留英文」。
- **失败静默**：所有外部请求、解析、存储读写均包 `try/catch`，断网、接口改版、字段缺失时功能降级而不报错。

## 8. 常见问题

**Q：悬浮球没有出现？**
确认访问的是 `pathofexile.com/trade/...` 页面，且扩展已启用；页面刷新一次；若站点结构改动导致注入失败，等待远端 `selectors` 更新或手动在设置页填写新的远端配置地址。

**Q：行内徽标显示"样本不足"？**
取样条数过少（挂售量小、赛季初期或冷门基底）。可在设置页调大取样数量，但注意过大取样会变慢并更容易触发频率限制。

**Q：估价与游戏内实际成交价差距大？**
估价基于同类挂售的统计中位数，不含议价与卖家心理价，冷门词缀组合偏差更明显。建议参考区间而非单点数值。

**Q：收藏的降价通知没收到？**
需系统允许该浏览器发送通知，且扩展 `alarms` 巡检周期为 30 分钟，最短也要等一个周期。

**Q：切换赛季要做什么？**
通常无需操作。若官方更改了市集 URL 中的赛季名，扩展会按当前页面 URL 自动识别；远端配置也会同步更新默认赛季。

**Q：开启了汉化，但页面上还有英文？**
汉化是词条命中式翻译，未收录的文案会保持英文。可在设置页「页面汉化」确认已保存设置并刷新页面；对仍然英文的条目，把它加进自定义词库（`英文=中文` 每行一条）保存即可，保存后无需刷新立即生效。若整块筛选器都是英文，检查「数据层汉化」开关是否被关闭。界面固定字段（按钮、Tab、区块标题、下拉选项、状态词、分页）已做到高覆盖，装备词缀在 0.3.1 起由官方词缀词库按 id 直译、实测 98% 命中；仍为英文的只剩暗金名/基底名、多段拼接的复合词缀与卖家备注，这是刻意的取舍（宁可保留英文也不输出半中半英）。

**Q：汉化会不会影响检索或导致页面异常？**
不会重写页面 `innerHTML`，也不改接口数据结构以外的字段。DOM 层只做两类改动：单条文本节点/属性原位换字；或某个元素整段命中后，清空它的文本子节点、保留其中的图标元素、写入一段译文（原文子节点保留在内存里）。所有改动都记录原文，关闭开关或点「在当前页面立即还原英文」会按原顺序逐条写回。若确实遇到样式或交互异常，先关掉「数据层汉化」并刷新页面，再反馈具体位置。

**Q：自定义词库和远端词库冲突时以哪个为准？**
优先级为 自定义词库 > 远端词库 > 内置词库，同一条英文原文始终取优先级最高的译法。

## 9. 隐私与合规

- 不采集、不上传任何账号凭据、Cookie 或角色信息；
- 唯一的外部请求为汇率数据（`poe.ninja`）、远端配置与远端中文词库（`raw.githubusercontent.com` 或用户自行填写的地址）与官方市集接口（`pathofexile.com`），全部只读；除官方词库地址外，不向任何第三方发送页面数据或使用行为；
- 汉化仅在本地改写页面文本，译文与自定义词库都在本地 `chrome.storage.local`，不上传任何页面内容。
- 不实现任何自动交易、自动私聊、自动组队行为，私聊文本仅写入剪贴板；
- 所有数据保存在浏览器本地 `chrome.storage.local`，卸载扩展即清除。
